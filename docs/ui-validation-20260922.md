# 화면 개편 검증 기록

확인일: 2026-09-22. Windows의 Chrome에서 검사했다. 자동 검사, 실제 자료 확인, 사용자 평가는 서로 다른 범위다. 예보관 인터뷰나 현장 사용성 평가는 수행하지 않았다.

## 테스트

| 검증 | 결과 |
| --- | --- |
| Spring 전체 테스트 | 172개 통과, 실패·건너뜀 없음 |
| Worker·프런트 상태·정적 화면 계약 | 244개 통과 |
| Playwright 전체 시나리오 | 97개 통과 |
| 정적 화면 빌드 | 통과 |
| 소스·자산·제3자 고지 감사 | development 모드 통과 |

320·360·390·393·768·1024·1280·1440 px 화면, 가로 전환, QHD·4K·8K 및 높은 DPR을 검사했다. 특히 아래 동작을 확인했다.

- 검색과 지도 선택으로 여는 지점별 예보, 열린 차트의 크기 변경
- 축약·상세 범례와 실제 격자 색의 일치, 0과 결측값의 구분
- LCC·메르카토르·위경도 도법에서 API 격자값과 렌더 픽셀의 일치
- 모바일 대기질·CCTV 팝업이 상단 정보와 하단 조작부를 가리지 않는지
- 거리 측정 중 핀치 줌이 점을 추가하지 않는지, 측정 결과를 닫으면 시간축이 돌아오는지
- 조회 실패 후 재시도, 취소한 이전 응답의 무시, 관측과 예보 시간의 구분
- 설정과 모달의 키보드 포커스, 모션 감소, 배경 탭의 재생 중단
- 3D의 지구본 전환, 모바일 드래그, Canvas 메모리 상한

GitHub의 Linux 브라우저 검사에서 CCTV 팝업이 처음 열릴 때 한 프레임 동안 잘못된 위치에
놓이는 문제가 확인됐다. CCTV·대기질·위험기상·좌표 팝업의 위치를 표시 즉시 계산하도록
수정했고, CCTV는 첫 프레임 전의 위치도 검사한다. 설정 버튼의 44 px 터치 영역 검사는
DOMRect의 부동소수점 오차만 소수 둘째 자리에서 정리한다.
또한 CCTV 지연 응답 검사는 요청 순번 대신 시간 초과·재시도·새 조회 단계별로 응답을
구분한다. 조회 도중 지도를 옮겨 이전 요청이 취소되는 경우에도 같은 복구 동작을 검사한다.

## 접근성과 성능

Lighthouse 스냅샷의 접근성·권장사항은 데스크톱과 모바일 모두 100이었다. 범례 버튼의 보이는 이름과 접근성 이름이 다르다는 별도 경고도 수정했다. 자동 검사 점수가 모든 이용자의 접근성을 보장하지는 않는다.

성능은 로컬 Spring 실행 환경에서 **390×844, DPR 2, CPU 4배 감속, Fast 4G** 조건으로 측정했다.

| 조건 | LCP | CLS |
| --- | --- | --- |
| 캐시를 무시한 새로고침, PerformanceObserver 측정 | 1,628 ms | 0.032 |
| 같은 화면 재방문, DevTools Performance 추적 | 1,221 ms | 0.00 |

첫 측정에서 FCP는 1,628 ms, DOMContentLoaded는 3,261 ms였고 정적 자료 전송량은 약 1.21 MB였다. Canvas 지도는 LCP의 직접 측정 대상이 아니다. 이 수치는 전체 기상자료 조회 시간이나 실서비스 사용자 지표를 뜻하지 않는다. INP의 실사용자 분포도 측정하지 않았다.

압축하지 않는 개발용 프록시에서 실제 운영 API를 연결한 경우에는 같은 모바일 제한 조건에서 LCP 5,058 ms, CLS 0.04가 나왔다. 해당 LCP 요소는 뒤늦게 도착한 특보 문구였다. 개발 프록시와 압축이 적용된 Spring 결과를 성능 개선의 전후 수치로 비교하지 않는다. 실제 운영 환경의 API 지연은 별도 관찰이 필요하다.

이번 변경에서 격자 색 계산을 재사용하고, Canvas 크기가 같으면 다시 할당하지 않으며, 숨긴 탭의 바람·예보 재생을 중단한다. 모션 감소 설정도 즉시 반영한다. 지도는 12MP, 바람 Canvas는 8MP 예산을 유지한다. 한글·숫자용 글꼴 하나를 미리 불러오며 기존 영문 고정폭 글꼴 3개의 불필요한 preload를 제거했다.

## 실제 자료와 캡처

README 이미지는 현재 소스를 브라우저에서 실행하고 운영 API로 받은 자료를 캡처했다. 바람·기온·일사강도는 `mock:false`, 부산 상세예보는 48개 시간 카드와 차트를 확인했다. AirKorea는 측정소 672곳과 관측시각을 확인했다. 시간 비교 GIF는 실제 예보시각을 바꿔 캡처한 화면을 이어 붙였다.

ITS CCTV는 이날 서울 지역 조회에서 상류 응답 지연을 확인했다. 이전 캡처나 시험용 카메라를 정상 운영 화면처럼 넣지 않았다. 확대 안내·조회 상태·재시도는 새 화면에서 확인했고, 정상 목록·재생·취소 경로는 브라우저 계약 테스트로 검증했다.

## 배포 범위

GitHub 업로드 검사에서 기존 개발 도구의 취약점도 확인해 `adm-zip`을 0.6.1,
`sharp` override를 0.35.4로 올렸다. 근거는 [ZIP 메모리 할당 문제](https://github.com/advisories/GHSA-7q85-xj36-vmfc),
[ZIP 심볼릭 링크 처리 문제](https://github.com/advisories/GHSA-vwc7-r8mq-g2x9),
[sharp의 libheif 문제](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c)다.
갱신 후 Cloudflare·E2E·지도 자료 도구의 npm 감사는 모두 취약점 0건이었다.
지도 자료 생성 결과의 크기·SHA-256이 기존과 같음을 확인했고 Worker 빌드와 배포 dry-run도 통과했다.

이 기록은 저장소의 소스와 화면 검증을 다룬다. 운영 Worker의 새 버전 배포나 GitHub release 발행을 뜻하지 않는다. 프로젝트 전체의 라이선스 검토 상태는 변경하지 않았으며 `--release` 감사는 기존 조건대로 차단된다.
